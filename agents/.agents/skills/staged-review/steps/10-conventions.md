# Step 10: Project conventions

**Applies when:** the project has written guidance, such as `AGENTS.md`, `CLAUDE.md`, a
contributing guide or style docs.

Check the change against the rules the project actually wrote down. Cite the guide and quote the
rule in each finding. Don't invent conventions the project hasn't stated. If an earlier finding
already covers the issue, add the rule to that finding instead of writing a new one.

Common areas:

- comment style and how much a comment may say
- how detailed docs should be
- prose rules for docs, commit messages and PR descriptions
- copies that must change together, such as mirrored schemas or contracts in two languages
- logging and telemetry conventions
- the checks the guide says to run before pushing. A PR that doesn't say they ran is missing
  evidence, not proof they failed. Say which it is.
